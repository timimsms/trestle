# Code of conduct

## The short version

Be straight with people and assume they are being straight with you.

## What that means here

This project runs on a particular habit: **name the problem rather than working around it.** The
most valuable contributions so far have been people saying "this decision cost me an hour and I
think it is wrong" — including about decisions the maintainers had already locked. That only works
if disagreement is cheap and safe.

So:

- **Criticize the decision, not the person.** "This rule is wrong because X" is the point of the
  project. "You clearly did not think about X" is not, and it makes the next person quieter.
- **Bring the evidence.** A claim with a reproduction ends an argument. A claim without one starts
  a long thread. This applies to maintainers at least as much as to contributors.
- **Being right is not a license.** Correct and unpleasant is still unpleasant, and it costs the
  project the people who would have argued with you next time.
- **Assume competence.** Somebody who hit a wall you did not hit probably has a repo shaped
  differently from yours, not a misunderstanding.

## Not acceptable

Harassment, personal attacks, demeaning comments about anyone's identity or background, unwelcome
attention, publishing others' private information, and sustained disruption of discussion.

## Reporting

Open a private security advisory (it is a working private channel for anything, not only
vulnerabilities), or email the address on the maintainer's GitHub profile. Reports are handled
privately, and you will get an acknowledgement.

Maintainers who do not follow this are subject to it exactly as anyone else is. If that is the
problem, say so — publicly if you feel able, privately if you do not.

## Scope

Applies in issues, pull requests, discussions, commit messages and code review — anywhere the
project happens.
